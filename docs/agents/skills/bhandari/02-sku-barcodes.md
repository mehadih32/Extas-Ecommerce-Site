## 1. SKU ≠ GTIN ≠ courier barcode — three different things

| Identifier | Who issues it | Scope | Where EXTAS uses it |
|---|---|---|---|
| **SKU** | EXTAS (ERP) | internal, unique per company (`ProductVariant.sku`) | picking, stock, invoices, feeds `id` |
| **GTIN (EAN-13)** | from a **GS1 company prefix** licensed by a GS1 member organisation (GS1 Bangladesh prefix is **894**) | global, open trade | only if EXTAS sells through retailers/marketplaces that require it; feed `gtin` |
| **Restricted Circulation Number (RCN)** | EXTAS, inside the GS1-defined prefixes **02 / 20–29** (and 040–049 within a company) | **closed environment only** — internal/in-store | in-house price/hang tags scanned by our own POS/warehouse |
| **Courier consignment ID + barcode/QR** | the courier (Steadfast, Pathao, RedX…) | per parcel | sticker — **always pulled from the courier, never generated by us** [HOUSE — blueprint standing rule] |

Facts: GS1 — each size/colour combination needs its **own GTIN** **[OFFICIAL — GS1]**; RCNs are for restricted circulation (a region or one company), encoded only in EAN-8/EAN-13/UPC symbols, no Application Identifiers **[OFFICIAL — GS1 GSCN 23-006]**; GS1 prefix 894 = GS1 Bangladesh, and a prefix doesn't indicate country of origin **[COMMUNITY — Wikipedia list of GS1 country codes; confirm with GS1 Bangladesh]**.
Google: if a product has no GTIN/MPN/brand (custom goods), `identifier_exists = no`; claiming "no" while an identifier exists triggers a warning **[OFFICIAL — Google Merchant Center Help]**.

## 2. EXTAS SKU format [HOUSE — to confirm against the ERP's existing SKUs before any change]

```
<CAT>-<STYLE>-<FIT>-<COLOR>-<SIZE>       PLO-PQ-CL-NVY-XL
CAT    3 letters   PLO polo · TEE t-shirt · SHT shirt · HD hoodie · SWS sweatshirt · TRK tracksuit · JGR jogger · TRS trouser · JKT jacket · PNJ panjabi · CMB combo
STYLE  2–4 chars   stable style code inside the category
FIT    2 chars     CL classic · SL slim · OV oversized · RG regular
COLOR  3 letters   from the colour dictionary (NVY, WHT, BLK, OLV, MRN, GRY …)
SIZE   S M L XL XXL 3XL
```
Rules:
1. **Uppercase ASCII letters, digits and dashes only**; ≤ 32 chars (fits Google's 50-char `id` and Meta's 100) **[HOUSE, within OFFICIAL limits]**.
2. **Never reuse a retired SKU** for a different garment (history, returns, feeds would mix).
3. **No meaning that changes** (no price, season or supplier in the SKU — those change; the SKU must not).
4. Re-production of the same style/colour/size with the same spec = **same SKU**; a real spec change (fabric, fit) = **new style code**.
5. Combos get their own SKU (`CMB-…`) that maps to component SKUs; stock of a combo = min of its components (B03).
6. The ERP is the issuer; the shop never creates SKUs (blueprint A3.3). If the ERP's existing format differs, **the ERP's format wins** and this section becomes a mapping table.

## 3. Barcodes on tags and in the warehouse [HOUSE]
- **Now (shop-only, own warehouse):** RCN-13 (prefix in 20–29 per GS1 Bangladesh's allocation for RCNs) or Code 128 encoding the SKU — scanned only by our own systems. Code 128 can carry the SKU letters directly; EAN-13 can't (digits only) **[HOUSE — Code 128 behaviour from general barcode knowledge; verify with the label printer vendor]**.
- **If wholesale/retail partners or marketplaces require GTINs:** get a GS1 Bangladesh company prefix, assign one GTIN per variant, store it in `ProductVariant.barcode`, and send `gtin` in feeds → **owner decision (fees)**.
- Print test before rollout: scan 20 labels from every printer at the owner's chosen sticker size (blueprint: "print clean and sharp at every supported size").

## 4. Decision tree — "does this item need a new SKU?"
```
Different garment, fabric, fit or construction?      → new style code → new SKUs
Same style, new colour?                               → new colour code → new SKUs for each size
Same style+colour, new size?                          → new SKU (size)
Same everything, new production batch?                → same SKU (track the batch as StockLot)
B-grade / defective?                                  → same SKU, B-grade stock location/flag (ERP bGradeAvgCost)
```

## 5. Worked example — supplier sends a "Navy" that is visibly darker
Same style, but colour differs from photos → customers would refuse. Decision: treat as a new colour `DNV` (Dark Navy) with its own SKUs and photos; don't mix into NVY stock. Lesson logged; colour dictionary updated with a swatch reference photo.
