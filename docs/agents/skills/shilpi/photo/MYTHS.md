# Shilpi · Doesn't work / myths (product photography)

| Myth | Evidence | Do instead |
|---|---|---|
| "Auto white balance is good enough." | Shopify says auto WB works for most situations, but colour-critical products need a reference frame; the blueprint requires a grey card/checker per colourway because wrong colour causes refusals. | Checker frame + correction per colourway. |
| "Adobe RGB looks richer, export that." | EIZO's tests: Adobe RGB-tagged images showed colour errors on several browser/device setups. | Export sRGB. |
| "Higher JPEG/WebP quality is always better." | WebP ~75–80 looks like 95 for photos; 100 wastes bytes (Specification.website). | Compress, verify visually on dark fabrics. |
| "Lazy-load every image for speed." | The first product image is usually the LCP element; lazy-loading it slows LCP (standard web.dev practice). | Eager + high priority for the first image only. |
| "Put keywords in alt text." | Google: keyword stuffing in alt may be seen as spam. | Describe the image (colour, view, model size). |
| "AI on-model images prove fit." | Blueprint and photoshoot brief: generated images are not evidence of fit or sizing. | Real fabric/colour photos stay the hero; honest disclosure line. |
| "A single crop works everywhere." | Placements need 4:5, 1:1, 9:16, 16:9 and white-background feed variants. | Shoot once with margins, crop many (P03). |

Sources: see P01–P06.
