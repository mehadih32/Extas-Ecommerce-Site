# Combo page audit (EXTAS r15)

Tested: `EXTAS-r15.html`, routes `#/combo/polo-duo`, `#/combo/office-trio`, `#/combo/polo-chino` (all 3 combos in `DB.combos`), templates Per-combo (auto), C1 Stacked, C2 Steps. Phone sizes 360×800, 393×852, 430×932 (isMobile, touch taps) and desktop 1280×800. Guest and logged-in (Rakib, VIP). Every flow went combo page → bag → checkout, and two went on to placing the order and the thank-you page. Source was only read, never edited.

**Summary: 22 findings: 6 money bugs, 7 wrong/misleading info, 7 UX, 2 cosmetic. 0 JS console errors. No horizontal scroll at any size.**

What is correct (checked against the data):
- Price box, summary, sticky bar and gallery badge all match the data:
  - Polo Duo: ৳1,500 vs ৳1,700, save ৳200 (12%)
  - Office Trio: ৳3,100 vs ৳3,850, save ৳750 (19%)
  - Polo + Chino: ৳2,050 vs ৳2,300, save ৳250 (11%)
- Per-item prices (৳850, ৳1,250, ৳1,450, ৳1,150) match the data.
- Bag and checkout totals equal the set price.
- Auto-apply works: 3 loose Office Trio items get −৳750. Remove one and the discount goes away. Nothing is left behind wrongly.
- Polo + Chino is "manual" (no auto-apply), and buying its items loose correctly gets no discount.
- Free delivery is applied on the bag, the checkout and the order.
- Sold-out sizes are greyed out and can't be tapped. Sold-out colours are disabled.
- Error messages name the item ("Pick a size for item 1 (Oxford Cotton Shirt).").

## Too complicated?

**Verdict: yes, for a first-time phone shopper it is too much.** The maths on the page is right. But the page asks for the same choices in two or three ways:
- colour: popular pairs **and** per-item swatches
- size: per item **and** a "same size" checkbox
- price: shown 4 times (gallery badge, price box with an item list, the set summary with the item list again, the sticky bar)

The pickers sit about 2 screens down while the Add button is visible from the start, so the usual first experience is an error toast. Office Trio adds a 3-step wizard (7 taps) on top. Behind the page, the bag and order shows don't add up (findings 7 and 8), which is what a cautious COD buyer checks before confirming.

**The 3 simplest changes that would help most:**
1. **Pickers first.** On phones, put the item cards (colour + size) right under the set price. Move "Popular pairs", the 5-thumbnail rail and the duplicate "Set summary" below them or remove them. If Add is tapped early, scroll to the first missing size and show the message there (no toast).
2. **One template: C1 Stacked for every combo.** Drop the step-by-step wizard (Office Trio goes from 7 taps to 4).
3. **One honest price line for a set everywhere after the page.** In the bag, checkout and thank-you, show the set as one row: "Polo Duo ৳1,500 (save ৳200)". Store the real item prices plus one set-discount line in the order. This fixes the confusing subtotal, the ৳1,033 rows and the wrong exchange charge (findings 1, 7, 8) together.
