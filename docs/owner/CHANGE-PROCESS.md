# নতুন আইডিয়া বা পরিবর্তন কীভাবে ঢুকবে — কোড চলার সময়, লাইভের পরে, ৬ মাস পরে

*১৯ অক্টোবর ২০২৬ · মালিকের প্রশ্ন (রাত ১০:৫৪) · PR 594-এর অংশ*

## মূল নিয়ম: একটাই সত্যের উৎস
- **মাস্টার রেজিস্টার** (কোন PR কী করবে) আর **ব্লুপ্রিন্ট** (পুরো নির্দেশনা) — এই দুইটা ফাইলই সব কিছুর মূল।
- কোড শুরু হলে এগুলো GitHub রিপোজিটরিতে `docs/` ফোল্ডারে থাকবে, কোডের সাথেই। প্রতিবার সাইট আপডেট হলে ব্যাকএন্ডের **PR রেজিস্টার** আর **ব্লুপ্রিন্ট ও ফাইল** ট্যাব নিজে থেকে নতুন হয় (PR 594) — আপনাকে GitHub-এ যেতে হবে না।
- বিল্ড এজেন্ট প্রতিটা PR শুরুর আগে রেজিস্টার পড়ে। তাই রেজিস্টারে যা উঠল, সেটাই বানানো হবে — কিছু হারায় না।

## ১. কোড চলার সময় নতুন আইডিয়া এলে
1. আইডিয়াটা আমাকে বলুন (এই চ্যাটে বা নতুন চ্যাটে), অথবা ব্যাকএন্ডের PR রেজিস্টারে **"নতুন ফিচার চাই / পরিবর্তন চাই"** ফর্মে লিখুন, অথবা টেলিগ্রামে প্রধান এজেন্ট জ্ঞানীকে (A360-01)।
2. আমি/জ্ঞানী আগে খুঁজব এটা **আগের কোনো PR-এর অংশ কিনা**। হলে সেই PR-এ তারিখসহ "আপডেট" যোগ হবে; না হলে নতুন PR নম্বর। (এটা আমাদের নিয়ম: অকারণে নতুন PR নয়।)
3. একটা **পরিবর্তনের নোট (Change note, CN-001, CN-002 …)** হবে: কী চাওয়া হলো, কোন PR, কোন স্টেজ, আপনার সিদ্ধান্ত।
   - উদাহরণ: **CN-001 = আপনার সার্ভার স্পেসিফিকেশন** (১৯ অক্টোবর রাত ১১:৩৩) — নতুন PR ৬০১–৬০৪, ব্লুপ্রিন্ট V2 → **V2.1**।
4. কোথায় বসবে:
   - **যে স্টেজ এখনো বানানো হয়নি** → ওই PR-এ যোগ হয়ে যায়; এজেন্ট যখন সেখানে পৌঁছাবে, নতুন নির্দেশসহই বানাবে। চলমান কাজ থামে না।
   - **যে অংশ আগেই বানানো হয়ে গেছে** → "পরিবর্তনের সারি"-তে ওঠে; চলমান ধাপ (wave) শেষ হলে এজেন্ট সেটা ধরে। চলমান কাজের মাঝখানে কিছু ভাঙে না।
   - **জরুরি বাগ** → সাথে সাথে আলাদা ছোট PR।
5. ব্লুপ্রিন্টের সংস্করণ বাড়ে: V2 → V2.1 → V2.2 …, প্রতিটার শুরুতে তারিখসহ পরিবর্তনের তালিকা।
6. ব্যাকএন্ডের "নতুন কী" ট্যাবে আর বেল-এ আপনি দেখবেন কোন PR যোগ/আপডেট হলো।

## ২. সাইট লাইভ হওয়ার পরে
একই পথ, শুধু দুইটা ধাপ বেশি:
- পরিবর্তন আগে **স্টেজিং** (আলাদা টেস্ট কপি)-তে বানানো ও টেস্ট হয় — ফোন, ট্যাব, ডেস্কটপের গেট, ফোনের ছবি আগে-পরে মিলানো।
- পাস করলে লাইভে যায়; সমস্যা হলে আগের সংস্করণে এক চাপে ফেরা।
- সাজানো/লেখা/অফার/মেনু ধরনের কাজ কোড ছাড়াই ব্যাকএন্ড থেকে আপনি নিজেই করবেন (সাইট বিল্ডার, পেজে এডিট মোড) — সেগুলোর জন্য PR লাগে না, শুধু সংস্করণের ইতিহাসে থাকে।

## ৩. ৬ মাস পরে বড় নতুন পরিকল্পনা এলে
1. আমাকে বা যেকোনো নতুন চ্যাটে বলবেন। আমার মেমোরি থাকুক না থাকুক, **রিপোজিটরির `docs/`-এ রেজিস্টার আর সর্বশেষ ব্লুপ্রিন্ট থাকে** — সেখান থেকে পড়ে শুরু করা হয় (ব্যাকএন্ড থেকে ডাউনলোড করেও দিতে পারবেন)।
2. পরিকল্পনাটা নতুন PR/স্টেজ হিসেবে রেজিস্টারে ওঠে, আগের কোন PR-এর সাথে যুক্ত তা নিজে থেকে দেখায় (PR 594)।
3. কোডের জন্য একটা **ছোট নির্দেশনা ফাইল** (যেমন V2.7 বা "Wave X brief") তৈরি হয় — শুধু নতুন অংশ, পুরো ব্লুপ্রিন্ট আবার লেখা লাগে না; মূল ব্লুপ্রিন্টের সংস্করণও সাথে সাথে বাড়ে।
4. কাজ শেষ হলে PR-এর অবস্থা "বানানো" হয়, ব্যাকএন্ডে তারিখসহ দেখা যায়।

## সংক্ষেপে
**আইডিয়া → রেজিস্টারে (আগের PR আপডেট বা নতুন PR) → পরিবর্তনের নোট → ঠিক জায়গায় সারিতে → বানানো ও টেস্ট → ব্লুপ্রিন্টের নতুন সংস্করণ → ব্যাকএন্ডে দেখা যায়।** কোনো ধাপে আপনাকে কোড বা GitHub দেখতে হবে না।
